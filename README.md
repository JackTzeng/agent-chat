# Agent Chat

把 **Claude Code** 和 **Codex** 兩個 CLI 包成一個聊天介面，可以組成 PM / Coder / QA 團隊互相派工，也能用 Telegram 遙控。每個 agent 有自己的名字、頭像和人設，回覆以 Markdown 顯示，agent 做出來的圖片和影片也能直接在聊天室裡看。

不用 `npm install`，只要有 Node.js 就能跑。

---

## 1. 事前準備（只做一次）

1. 安裝 **Node.js 18 以上**：https://nodejs.org （選 LTS 版本）
2. 開終端機（Windows 用 PowerShell），安裝兩個 CLI：
   ```
   npm i -g @anthropic-ai/claude-code @openai/codex
   ```
3. 分別登入一次：
   ```
   claude      ← 照畫面登入 Claude 帳號，登入完輸入 /exit 離開
   codex       ← 照畫面登入 ChatGPT 帳號，完成後 Ctrl+C 離開
   ```
   **一定要先在終端機確認這兩個指令能正常用**，聊天介面只是在背後呼叫它們。
4. （選用）想讓 Google 的模型也加入「互相檢查」：到 https://antigravity.google/download 安裝 Antigravity CLI，在 PowerShell 輸入 `agy` 用 Google 帳號登入一次，再參考下方「Google Antigravity 成員」。

## 2. 啟動

- Windows：雙擊 `start.bat`（會自動打開 **http://localhost:3939**）
- 或在這個資料夾開終端機，輸入 `node launcher.js`

**你自己的設定**（允許的資料夾、CLI 路徑、遠端連線）寫在 `local-settings.txt`：把 `local-settings.example.txt` 複製一份、改名成 `local-settings.txt`，用記事本修改，一行一個「名稱=值」，例如：

```
AGENT_ALLOWED_ROOTS=C:\EM_reports_copy
```

- 這個檔不會進 git，更新時不會被蓋掉；中文路徑沒問題
- 改完按左下角「⬆️ 更新／重新啟動」→「🔄 只重新啟動」就生效，不用重開 start.bat
- 存檔時注意檔名要是 `local-settings.txt`（不是 `local-settings.txt.txt`；在檔案總管「檢視」勾「副檔名」就看得到）
- 舊版寫在 start.bat 或 start.local.bat 的 `set` 設定會自動搬進來

### ⬆️ 一鍵更新／重新啟動

不用再 `git pull` 再重開 start.bat：

- 網頁左下角「⬆️ 更新／重新啟動」：顯示有哪些新功能，按「⬆️ 更新並重新啟動」就會下載、重啟，頁面自動重新整理；只想重開伺服器就按「🔄 只重新啟動」
- Telegram：`/update`（檢查並更新）、`/restart`（重新啟動），好了會通知你；有成員正在工作時會先問你，確定就傳 `/update yes`
- 伺服器每 6 小時在背景檢查一次，有新版時「⬆️ 更新」旁邊會出現「新」
- **安全網**：新版本一分鐘內起不來，會自動退回原本的版本並告訴你；你自己改過的程式檔不會被蓋掉（會停下來告訴你是哪些檔）；舊的 start.bat 裡的 `set` 設定會自動搬到 local-settings.txt
- 重新啟動時，正在進行的任務會暫停，之後回覆就能繼續；沒勾「記住這台電腦」的話要再輸入一次密碼
- 需要用 v3.6.0 以後的 start.bat 啟動（它會執行 launcher.js，由 launcher 負責重新啟動）

## 3. 自訂團隊：編輯 `agents.json`

第一次啟動後，資料夾裡會出現 `agents.json`（從 `agents.example.json` 複製來的）。之後都改 `agents.json`，它不會被 git 更新蓋掉。

**最簡單的方式是直接在網頁上設定**，不用手動改檔案：
- **頭像**：在表單裡點頭像，可以從列表挑 emoji、上傳圖片、Ctrl+V 貼上圖片，或把圖片拖進去
- 左邊最下面的「**＋ 新增成員**」：填名稱、職責、引擎、模型、強度、權限、可交接對象和人設，也可以一鍵套用 PM / Coder / QA / 文件 / 研究範本
- 成員卡片右下角的 ⚙️，或聊天室上方的「⚙️ 設定」：編輯或刪除成員
- 在「👥 全員」頁按「⚙️ 團隊設定」：修改工作流程和自動轉交上限

網頁上的修改會直接寫回 `agents.json`，馬上生效，不用重開伺服器。模型、強度和權限從下一句就開始套用；名稱、職責、人設和工作流程則要「開新對話」才會生效（表單裡有勾選項可以順便開新對話）。

以下是 `agents.json` 的格式，想直接改檔案時可以參考：

範本預設是三人團隊：🎩 克勞德先生（PM）、📜 許代書（Coder）、🔍 小安（QA）。

### 整份檔案的結構

```
{
  "maxRelayHops": 12,        ← 成員之間自動轉交的上限，避免無限來回
  "teams": [ … ],            ← 小組：每組有自己的名稱、圖示與工作流程（見第 6 節）
  "telegram": { … },         ← Telegram 遙控，見第 5 節
  "agents": [ … ]            ← 成員清單；每位成員用 "team" 指定所屬小組
}
```

### 每位成員的設定

```
{
  "id": "kai",                 ← 英數代號，不要重複（對話記錄用它存）
  "name": "許代書",             ← 顯示名稱，也是 @ 的名字
  "avatar": "📜",              ← 頭像（emoji）
  "role": "Coder · 實作",       ← 職稱，會告訴其他成員
  "engine": "codex",           ← "claude"、"codex" 或 "agy"（Google Antigravity）
  "model": "gpt-6-luna",       ← 模型，留空 = 該 CLI 的預設
  "effort": "max",             ← 推理強度，留空 = 預設
  "sandbox": "workspace-write",← 權限，見下方表格
  "cwd": "./workspace",        ← 工作資料夾
  "canHandoffTo": ["qa", "hikari"],  ← 可以把工作交給誰（填 id），不寫 = 所有人
  "persona": "你叫許代書……"     ← 人設與職責
}
```

### 模型與推理強度

| engine | model 範例 | effort 可用值 |
|---|---|---|
| claude | `claude-opus-5-5`、`claude-sonnet-5-5`、`claude-haiku-5-5`、`claude-fable-5-2`，或簡寫 `opus`、`sonnet` | `low`、`medium`、`high`、`xhigh`、`max` |
| codex | `gpt-6.2-astra`、`gpt-6.2-sol`、`gpt-6.1-sol`、`gpt-6-astra`、`gpt-6.1-terra`、`gpt-6-sol`、`gpt-6-luna`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna` | `low`、`medium`、`high`、`xhigh`、`max` |

| agy | `gemini-3.8-flash-high`（免費方案可用）、`gemini-3.8-flash-medium` 等；`gemini-4-argon-*` 需方案支援（以 `agy models` 為準；模型代號已包含強度，也可再用 `effort`） | `low`、`medium`、`high`、`xhigh`、`max`（依模型） |

- 強度越高，想得越久，也越耗用量額度
- 能用哪些模型取決於你的訂閱方案；填了方案不支援的模型，聊天室會顯示錯誤訊息
- Codex 在終端機輸入 `codex.cmd` 後打 `/model`，可以看到你帳號目前能用的模型

### 分工與工作流程

- `workflow` 寫整個團隊的流程，每位成員都看得到
- `persona` 寫個人的職責，例如「你不親自寫程式碼」
- `canHandoffTo` 限制交接對象；回覆裡 @ 了不允許的人，系統不會轉交
- 改完 `agents.json` 要重開 `start.bat`，**每位成員也都要按一次「新對話」**，新的分工才會生效（流程說明只在每段對話的第一句送出）

### 🔁 輪流工作

預設每位成員都可以同時工作。會改同一批檔案的團隊（例如 PM / Coder / QA）建議勾選「🔁 和團隊輪流工作」：勾選的成員之間同一時間只有一位在動手，其他的排隊。沒勾的成員（例如負責環境更新的成員）不受限制，隨時都能工作。

可以在成員設定裡勾，或在「⚙️ 工作流程」的「輪流工作的成員」一次勾選。

### 額外可以存取的資料夾

成員預設只能讀寫自己的工作資料夾。需要讀寫其他位置（例如 `C:\EM_reports_copy\EM_DATA`）時，在成員設定的「額外可以存取的資料夾」新增完整路徑，並選擇：

- **可讀寫**：可以讀取、修改、新增檔案；任務的變更清單也會追蹤這個資料夾（檔名前面會標 `[資料夾名稱]`）
- **唯讀**：只能讀取。對 Codex 由沙箱強制擋下寫入；對 Claude 是每一輪都明確要求不可修改（Claude Code 沒有單一資料夾唯讀的開關）

重要的原始資料建議只給唯讀，或先複製一份再給可讀寫。

想加更多成員，照格式複製一段即可。Windows 路徑要寫成 `"C:/Users/你的帳號/project"`（斜線方向改成 `/`）。

### 權限設定（重要）

聊天介面沒辦法跳出「要不要允許這個操作？」的確認視窗，所以權限要事先決定：

| 引擎 | 設定值 | 意思 |
|---|---|---|
| claude | `"plan"` | 只看不改，只會提出計畫 |
| claude | `"acceptEdits"` | 可以讀寫檔案；需要執行指令時會被擋下，並在聊天室回報 |
| claude | `"auto"`（預設） | Claude 自己判斷風險，低風險直接執行、有風險的擋下 |
| claude | `"bypassPermissions"` | **安全修補後 Web/Telegram 禁用；請在本機 CLI 人工使用** |
| codex | `"read-only"` | 只能讀 |
| codex | `"workspace-write"`（預設） | 只能在工作資料夾內寫檔與執行指令 |
| codex | `"danger-full-access"` | **安全修補後 Web/Telegram 禁用；請在本機 CLI 人工使用** |

如果成員一直說「沒有權限執行指令」，可以把 permissionMode 改成 `auto`。

## 4. 用手機瀏覽器連（選用）

**建議用 Tailscale**（免費）：電腦和手機都裝 Tailscale、登入同一個帳號，兩台裝置就像在同一個私人網路裡。

1. 用遠端模式啟動，**一定要設密碼**：
   ```
   # PowerShell
   $env:HOST="0.0.0.0"; $env:ALLOWED_HOSTS="你的Tailscale-IP"; $env:ACCESS_TOKEN="至少16字元的隨機長密碼"; node server.js
   ```
2. 手機瀏覽器打開 `http://電腦的Tailscale IP:3939/（在登入視窗輸入密碼，網址不得攜帶 token）`
   （第一次帶 token 就好，之後這支手機會記住）

⚠️ 這個介面等於可以遙控你電腦上的 AI 執行指令。**不要**把 3939 port 直接開到公開網路上。

## 5. Telegram 遙控（選用）

設定好之後，在手機的 Telegram 傳訊息就能派工，每位成員做完一輪也會把結果（含圖片）推送到 Telegram。不需要 Tailscale，也不用開任何 port。

**設定步驟（全部在網頁上完成，不用改檔案、不用重開）：**

1. 在 Telegram 搜尋 **@BotFather**，傳 `/newbot` 建立 bot；已經建好的話，選你的 bot 按「Copy」複製 token
2. 在網頁左下角按「📱 Telegram：按這裡設定」（或全員頁上方的「📱 Telegram」）
3. 貼上 token，按「儲存並連線」，顯示「已連線：@你的bot」就成功了
4. 按「產生配對碼」，在手機打開你的 bot，把 6 位數配對碼傳給它
5. 收到「✅ 配對成功」就完成了，傳 `/help` 看所有指令

**Telegram 裡的用法：**

| 輸入 | 作用 |
|---|---|
| `/task 目標` | 開始新任務（依照目前對象所屬小組的工作流程） |
| `/task 報表組 目標` | 指定由哪個小組執行 |
| `/status` | 所有進行中任務的進度（依小組列出） |
| `/approve`、`/reject 意見` | 核准或退回交接；同時有好幾件時加編號，例如 `/approve #3` |
| `/cancel` | 停止任務（好幾件時加 `#編號`） |
| 直接打字 | 任務在等你回覆時回給那位成員；好幾件同時在等時，開頭加 `#編號`（例如 `#3 用 A4 格式`）；否則交給目前的對象 |
| `@小安 幫我再測一次` | 交給指定成員，不切換對象 |
| `/list` | 成員、模型與工作狀態 |
| `/to 許代書` | 切換對象 |
| `/stop` | 全部停止 |
| `/new` | 目前對象開新對話 |
| `/usage` | Claude / Codex 的 5 小時與每週用量額度 |
| `/mute`、`/unmute` | 暫停 / 恢復推送 |

⚠️ **bot token 等於鑰匙**：拿到的人可以冒用你的 bot，不要貼到任何地方（外流了就到 @BotFather 按 Revoke 換一組）。只有配對過的帳號能下指令，其他人傳訊息只會被拒絕。token 存在 `agents.json`，不會上傳到 GitHub。

公司網路如果擋了 `api.telegram.org`，黑色視窗會顯示「Telegram 連線失敗」。這種情況只能在可以連外的網路下使用。

## 6. 任務與工作流程（建議的合作方式）

**工作流程**定義團隊怎麼合作；**任務**是照著流程跑一次的工作。

### 定義工作流程

在「👥 全員」頁按「⚙️ 工作流程」（或右上角「⚙️ 團隊設定」）。每個階段可以設定：

| 欄位 | 說明 |
|---|---|
| 名稱與負責成員 | 例如「實作」由許代書負責 |
| 要做什麼 | 這個階段的工作內容與規則 |
| 交付物 | 例如 PLAN.md、測試報告 |
| 完成後可以交給 | 可以勾選多個（例如測試完成可以交給「驗收」，也可以退回「實作」）；都不勾就是最後一個階段 |
| 🔒 交出前需要你核准 | 例如 PM 的計畫要你看過才能派工 |

另外可以寫「其他規則」（所有成員都會看到），以及每件任務最多交接幾次。範本是 PM → Coder → QA 標準流程。

儲存後會寫成工作資料夾裡的 **WORKFLOW.md**，每次修改的舊版本也會備份在 `data/workflow-history`。

### 👥 小組：不同專案交給不同團隊

每個小組有自己的成員、工作流程與任務，不同小組的任務可以**同時進行**（每個小組一次一件）。

1. 全員頁任務列上方是小組分頁，按「＋ 小組」建立新小組（例如「📊 EM 報表組」）；工作資料夾會自動帶入（例如 `./workspace/em`），系統會建好這個資料夾
2. 到成員設定的「小組」欄位，把成員分進這個小組（也可以直接新增成員）；工作資料夾會自動換成小組的資料夾
3. 選好小組分頁後按「⚙️ 工作流程」，設定這個小組自己的階段
4. 在小組分頁下輸入任務目標，任務就由這個小組執行

- 成員只會看到、只能轉交給同組的成員；🔁 輪流工作也只在同組內排隊
- 📁 每個小組有自己的**工作資料夾**，新成員預設在這裡工作。舊的小組可以在「⚙️ 工作流程」填上資料夾，勾「把組內成員的工作資料夾也改成這裡」一次搬過去（原本的檔案不會搬，成員會開新的對話）
- 如果兩個小組還是用同一個資料夾，設定畫面會顯示 ⚠️；系統會把後面那組的檔案改名成 `TASK-小組名.md`、`WORKFLOW-小組名.md`，不會互相覆蓋
- 還是某個階段負責人的成員，要先在流程裡換掉負責人才能移到別組；小組要先清空成員、沒有進行中的任務才能刪除
- 舊的設定會自動變成一個「🛠 開發組」，原本的成員與流程都不變

### 執行任務

1. 到「👥 全員」頁，在下方輸入任務目標，按 Enter，任務會從第一個階段開始
2. 上方的任務面板會顯示目前進行到哪個階段
3. 成員問你問題時，面板會顯示「⏳ 等你回覆」，直接在下方輸入框回覆
4. 到了需要核准的階段，面板會列出交接內容與變更的檔案，按「✅ 核准」或填意見後「↩️ 退回」
5. 最後一個階段完成後，任務就結束了；「📜 任務紀錄」可以看到完整經過

### 系統會自動幫你做的事

- **每件任務都開新對話**：跟自由聊天分開，對話不會越拉越長
- **每一輪都提醒成員**：身分、職責、整個流程、目前負責的階段、交接方式
- **固定的交接格式**：成員做完要在回覆最後寫 `【交接】給：名字`，系統依流程檢查，交給不該交的人會被退回重寫
- **附上變更清單**：自動比對工作資料夾，把這個階段實際新增、修改、刪除的檔案附給下一位，不靠成員口述
- **輪流工作**：勾了「🔁 輪流工作」的成員同一時間只有一位在動手，其他的排隊；沒勾的成員不受限制
- **任務紀錄**：工作資料夾的 `TASK.md` 是目前任務的狀態與交接紀錄，所有任務也都存在 `data/tasks`

Telegram 也能操作任務：`/task 目標`、`/status`、`/approve`、`/reject 意見`、`/cancel`。任務在等你回覆時，直接打字就會回給那位成員。

### 🧭 Harness：讓團隊可控、可衡量、可靠

Agent = Model + Harness。模型是大腦，Harness 是圍繞模型的執行系統。在「全員」頁的任務列按「🧭 Harness」可以看到六個部分：

| 要素 | 在這裡的做法 | 在哪裡設定 |
|---|---|---|
| 📏 守則（Guides） | 從過去的失敗整理出的規則，**只告訴適用範圍內的成員**（見下方）。成員在回覆中另起一行寫 `【守則建議→要遵守的人】…`、或你退回交接時寫的意見，都會變成「守則建議」，**你核准後**才會變成守則 | 🧭 Harness → 守則 |
| 🧪 自動檢查（Sensors） | 每個階段可以設定最多 5 個檢查指令（例如 `npm test`）。成員寫好交接後，系統在它的工作資料夾執行，**全部通過才交出**；沒通過就把錯誤輸出退回給同一位成員修正，通過的結果會附給下一位 | ⚙️ 工作流程 → 每個階段的「🧪 自動檢查」 |
| 🔁 循環與預算（Agentic Loop） | 同一個階段最多重做幾次（被退回或檢查失敗都算）、每件任務的交接上限與時間上限。超過就暫停、交給你決定；你回覆後會再給一次預算 | ⚙️ 工作流程 |
| 🧠 外部記憶（Memory） | 成員寫 `【決策】…` 會存進專案記憶，任務完成時自動記下成果；每一輪附上同一小組最近 10 筆，完整內容在工作資料夾的 `MEMORY.md`（只寫同小組的紀錄）。記憶只當參考，不會被當成指令 | 🧭 Harness → 記憶 |
| 🔐 權限（Permissions） | 一覽每位成員能不能改檔案、可存取哪些資料夾、哪些階段要核准 | 成員的 ⚙️ 設定、`local-settings.txt` 的 `AGENT_ALLOWED_ROOTS` |
| 📊 觀測（Observability） | 每一輪的耗時、tokens、≈API 價、出錯、插話，以及檢查、預算暫停、守則建議等事件；存在 `data/harness/runs.jsonl` | 🧭 Harness → 紀錄 |

#### 守則的適用範圍

每條守則都有適用範圍，成員只會收到和自己有關的：

| 範圍 | 誰會收到 |
|---|---|
| 👤 成員 | 只有那位成員 |
| 🧩 階段 | 只在任務進行到那個階段時，負責的成員才會收到 |
| 👥 小組 | 那個小組的成員 |
| 🌐 全體 | 所有小組的成員（獨立成員除外） |

- **預設給被提報的對象，不會擴大到全體**：你退回誰的交接，那則意見就預設只給誰；成員寫 `【守則建議→許代書】…` 就給許代書（也可以寫階段或小組名稱），沒點名就只給提出的成員自己。核准前可以在下拉選單改範圍
- 核准後也可以隨時改範圍；📌 設為必讀會優先放進提示詞；⏸ 暫停使用會保留守則、但不告訴任何人
- 每一輪最多放 1200 字的守則（在「⚙️ 工作流程」調整），越具體的越優先；放不下的會告訴成員「另有幾條，看 GUIDES.md」
- 工作資料夾裡的 `GUIDES.md` 只寫在那裡工作的成員要遵守的守則，別的小組的資料夾不會有
- 守則分頁上方會顯示每位成員實際收到幾條、多少字，黃色代表有放不下的

### 🧍 獨立成員（例如記帳員）

不屬於 PM → Coder → QA 工作流程的常駐助手。在成員設定勾「🧍 獨立成員」，或按「📒 套用記帳員設定」：

- 訊息直接交給它處理、直接回覆，不建立任務、不寫 TASK.md、不交接、不需要核准
- **角色設定檔**：例如 `ledger/agent/記帳員.md`（相對於工作資料夾），每一輪重新讀取
- **成員專屬環境變數**：例如 `LEDGER_SHEET_ID=…`，只有這位成員拿得到；不能設定 PATH、金鑰之類的變數
- **最小權限（Claude）**：權限選「default」，可用工具填 `Bash,Read`，允許規則填 `Bash(ledger/ledger.cmd *)`：不在清單裡的指令與檔案修改，Claude Code 會直接拒絕
- **Telegram**：
  - 主 bot 用前綴：`/記帳 昨天晚餐 350`；或 `/to 記帳員` 切過去，之後每句都給它（`/to 克勞德先生` 切回來）
  - **專屬 bot**（建議）：在 BotFather 另外開一個 bot，把 token 貼在成員設定。那個聊天的每句話都交給記帳員，適合「對」「撤銷」這種接續對話
  - 照片和檔案會存到 `attachments/`，路徑交給成員
  - 可以限定只接受哪些 Telegram 帳號（其他帳號的訊息不處理）
- **📜 紀錄**：成員頁的「📜 紀錄」可以看每一輪的輸入、執行的指令與結束碼、回覆和錯誤（`data/audit/`）

### 🔄 換班：對話太長時換成全新的對話接手

每位成員的對話越長，CLI 越會自動壓縮前面的內容，細節（早期定的規格、某個檔案為什麼這樣改）可能就此遺失。換班的做法：

1. 成員卡片上的 `🧠 42%` 是這段對話大約用了多少（Claude 從每一輪回報的 token 數估計；Codex 從它自己的紀錄檔讀取）
2. 超過「⚙️ 工作流程」裡設定的比例（預設 40%，0 = 關閉）時，下一輪開始前，系統先請成員寫一份**交班筆記**（目標、已完成、進行中、下一步、重要決定、相關檔案）
3. 接著換成全新的對話，第一句就附上交班筆記，然後才處理原本的訊息；卡片會顯示「第 2 班」
4. 也可以在成員的對話頁按「🔄 換班」手動換班

自由聊天和任務都適用；換班那一輪不算任務的交接次數。交班筆記會顯示在對話裡，也存在 `data/harness/shifts`。

### 查詢歷史決策（v3.16）

在 `local-settings.txt` 加入 `AGENTCHAT_RECALL_AGENT=成員ID`，重新啟動後，直接在網頁或 Telegram 問該成員「現在還能不能跑 run07？」。Claude 或 Codex 團隊成員可依編號找到最近十筆以外的決策。查詢範圍涵蓋同小組與全體共用紀錄。每次最多引用四筆原文，附記憶編號、作者與 UTC 時間，由新到舊排列。守則繼續由 Harness 依核准範圍派送。

要依主題查詢，可輸入「查決策 如何驗收交付成果」。預設使用本機關鍵字。啟用本機語意查詢時，請先在管理者信任的目錄準備 Python 3.11 以上的虛擬環境與模型，例如在安裝目錄執行以下 PowerShell 指令：

```powershell
py -m venv data/recall-venv
data/recall-venv/Scripts/python -m pip install mem0ai==1.0.11 onnxruntime==1.32.0 tokenizers==0.23.3
py recall_mem0.py --download data/recall-model
```

把虛擬環境的 `python.exe` 與模型資料夾的**絕對路徑**分別填入 `local-settings.txt` 的 `AGENTCHAT_RECALL_PYTHON`、`AGENTCHAT_RECALL_MODEL` 並重啟。下載程式會核對模型與詞表的 SHA-256。查詢時在本機用多語模型與 Mem0 的 Qdrant 向量搜尋元件比對原文，查完釋放記憶體。編號精確比對不需啟動 Python。模型失敗或超時時，會在查詢提示中註明改用關鍵字。移除 `AGENTCHAT_RECALL_AGENT` 並重啟即可停用。

### 🗜 壓縮指令輸出（rtk，只限 Claude 成員，v3.11）

[rtk](https://github.com/rtk-ai/rtk) 會把 git、測試、建置等指令的輸出精簡後再交給 AI，省 token，對話也不容易被長長的紀錄撐大。

1. 在這台電腦安裝 rtk：PowerShell 執行 `winget install rtk-ai.rtk`（**不用**跑 `rtk init -g`）
2. 到成員設定勾「🗜 壓縮指令輸出」（只有 Claude 團隊成員有這個選項），卡片出現「🗜 rtk」就是生效了
3. 「📏 上下文」面板可以按「📊 看 rtk 省了多少」

說明：
- 只影響勾選的成員：Agent Chat 啟動它時用 `--settings` 額外接上 hook，不改你自己的 `~/.claude/settings.json`
- hook 經過 `rtkhook.js`：只採用 rtk 的指令改寫，**不讓 rtk 替成員核准指令**（rtk 舊版有自動核准的問題），權限照原本的設定；rtk 出錯就當作不改寫
- 只壓縮 Bash 執行的指令；Claude 內建的讀檔、搜尋工具不經過 rtk
- 獨立成員、有限制工具的成員不使用；Codex、agy 成員不適用
- 如果你之前跑過 `rtk init -g`，你自己的 Claude Code 也會被壓縮，面板會提醒你

### 📄 附件先轉 Markdown（markitdown，選用）

[markitdown](https://github.com/microsoft/markitdown)（Microsoft，MIT）把 PDF、Word、Excel、PowerPoint 轉成 Markdown。成員直接讀 PDF／Office 檔常常讀不全或很耗 token，先轉成 Markdown 比較省也比較準，適合 GMP 文件、規格書、報表。

Agent Chat 不內建它（不加 Python 相依），做法是裝在這台電腦，再用一條守則請成員自己轉：

1. 安裝（需要 Python 3.10 以上）：PowerShell 執行 `pip install "markitdown[all]"`，再執行 `markitdown --help` 確認找得到
2. 「🧭 Harness → 守則」最下方的「📋 常用守則範本」選「📄 附件先轉 Markdown」，內容會填進輸入框；選好適用範圍後按「新增」
3. 守則內容（也可以自己改）：
   > 收到 PDF／Word／Excel／PowerPoint 附件時，先執行 markitdown "檔名" -o "檔名.md" 轉成 Markdown，再讀轉出來的 .md；表格、數字以原檔為準，轉檔結果有疑問時說明並回頭核對原檔。

注意：
- 轉檔要執行指令，只有能執行指令的成員做得到（Claude `auto`、Codex `workspace-write`、agy `write`）。Claude `acceptEdits`／`plan`、agy `read` 的成員做不到；請把守則的範圍設給負責轉檔的成員，讓他轉好再交給其他人
- 有「限制工具」的 Claude 成員，要在允許清單加上 `Bash(markitdown:*)`
- 掃描成圖片的 PDF 沒有文字可轉（markitdown 不做 OCR），轉出來會是空的或很少字
- 轉檔結果是給 AI 讀的輔助；正式的數字、簽核內容仍以原始文件為準

### ⏸ 暫停／▶ 重啟專案（v3.10）

側邊欄最上方的「⏸ 暫停專案」（Telegram：`/pause 原因`、`/pausenow`、`/resume 指示`）：

- **暫停**：選整個專案或某個小組。正在工作的成員做完這一輪（或立刻停下），有進行中對話的成員各寫一份交班筆記；之後同事轉交、任務交接、排程都先排隊，不會叫醒成員。你直接傳給成員的訊息照樣處理；獨立成員不受影響
- **重啟**：被停下的工作接著做、排隊的訊息放行，寫過筆記的成員用全新的對話帶著筆記接手；可以加一句補充指示給所有人
- 暫停狀態和排隊的訊息都會存檔，程式重新啟動也不會自己恢復；暫停期間的排程直接略過，暫停的時間不算進任務的時間預算
- 對話少於 20000 tokens 的不寫筆記（直接接著原本的對話）；要調整就在 `agents.json` 的 `harness` 加 `"pauseNoteTokens": 數字`（0＝都寫）

### 📏 上下文瘦身（v3.9）

- **開頭說明沒變就不重送**：身分、團隊、交接規則、守則、記憶每一輪都一樣，重複送會讓 CLI 的對話紀錄越堆越長。同一段對話只在第一輪、內容有變動、或每 N 輪（預設 10，設定可改，0＝每輪都送）完整送一次，其餘只送一行「說明沒有變動」
- **📏 上下文用量**（Harness 面板）：每位成員每輪固定帶多少字（角色／守則／記憶／其他）、已省略幾輪、對話用量；超過 4k 字標黃，可以去精簡守則或記憶
- **排程每次開全新的對話**，只帶上次結果的摘要；要接著上次的對話，在排程勾「記得上次的對話」

自動檢查的指令會用你的 Windows 帳號、在負責成員的工作資料夾執行（環境變數一樣經過白名單過濾），只能在登入後的網頁設定，請只填你看得懂的指令。檢查跑太久會被強制停止（預設 300 秒）。

## 7. 自由聊天：讓成員互相 @

成員的回覆裡只要出現 `@另一位的名字`，伺服器就會把那則回覆自動轉給對方；對方回覆時再 @ 回來，也會自動轉回去。

- 用法：跟克勞德先生說「寫好後請 @許代書 審查」，接下來就會自動來回
- **你自己的訊息裡寫 @名字**，也會同時把訊息交給那位成員（例如對許代書說「@克勞德先生 請協助」，兩位都會收到）
- 左邊的 **👥 全員** 可以照時間順序看所有人的對話，轉交過程會顯示成「📨 A → B」
- 對方忙碌中的話，訊息會排隊，等它做完再處理
- 為了避免無限來回，自動轉交有上限，預設 12 次，可以在 `agents.json` 最上面的 `maxRelayHops` 修改
- 想中斷就按「停止」，或在全員頁按「全部停止」
- 團隊名單只在每段對話的第一句告訴 agent，所以**新增或改名成員後，要按「新對話」**它們才知道同事是誰
- 兩位預設共用 `workspace` 資料夾，所以看得到彼此的檔案；如果改成不同資料夾，交接時要寫完整路徑

## ⏰ 排程：定時叫成員做事

左下角「⏰ 排程」→「＋ 新增排程」：選成員、寫下要做什麼、多久一次。例如：

| 名稱 | 成員 | 多久一次 | 要做什麼 |
|---|---|---|---|
| 檢查新的超標資料 | 克勞德先生 | 平日每小時（08:00～18:00） | 檢查 EM_DATA 有沒有新的超標資料，有的話整理成表格 |
| 整理帳目 | 記帳員 | 平日 08:30 | 整理昨天的帳並寫進表單 |

- **不會一直吵你**：成員檢查完沒事就回「【無異常】」，你不會收到通知；有異常或失敗才傳到 Telegram，而且和上次一樣的內容不重複發（也可以設定成每次都通知或不通知）
- **獨立的對話**：排程有自己的對話，會記得上次檢查的結果，也不會把你和成員的主對話越拉越長
- **不重複、不漏掉**：每一次觸發都會記下來，重新啟動後不會重做同一次；電腦或程式關著時錯過的，開機後補做一次（錯過好幾次也只補一次）；上一次還沒做完就略過這一次
- **沒事就不要叫醒成員**（省 AI 額度）：
  - 🔍 **前置檢查**：填一行指令（例如 `node pm/check_dispatch.mjs`），到點先跑它，**沒有輸出 = 沒事，直接跳過、不叫醒成員、不花 AI 額度**；有輸出才叫醒成員並把輸出給他看。檢查腳本可以請成員幫你寫（沒有待辦時不要印任何東西）
  - ⏸ **成員可以先暫停**：成員確認所有工作都完成時回「【排程暫停】原因」，排程就先暫停（Telegram 會告訴你一次），**有新任務開始時自動恢復**；你自己按暫停的不會被自動恢復
- 每小時、每 30 分鐘這種間隔會對齊整點；最短每 15 分鐘一次（每次都會用到 CLI 額度，表單會估算每天、每週幾次）
- **成員提出排程**：成員不會再自己去建 Windows 排程，而是在回覆中寫「【排程建議】平日 08:30｜整理昨天的帳」（也可以附前置檢查：「【排程建議】每小時｜檢查派工｜先檢查：node pm/check_dispatch.mjs」），你在「⏰ 排程」或 Telegram 核准後才生效
- 執行紀錄在「⏰ 排程」最下面；問題回報也會附上排程狀態
- Telegram：`/timers` 看全部排程；`/timer 編號 run`（立即執行）、`on`／`off`（開關）、`ok`／`no`（核准或略過成員的建議）

## 8. 🏢 辦公室

左邊的「🏢 辦公室」（或全員頁右上角的「🏢 辦公室」）把團隊畫成一棟等角像素風格的辦公室：**每個小組一間辦公室**，獨立成員各有一間小隔間，下方是大家共用的茶水間・會議室。

| 你看到的 | 代表 |
|---|---|
| 坐在自己的桌子前、螢幕亮著在打字 | 正在工作；頭上的泡泡顯示它正在做什麼（例如「⚙️ 執行：npm test」） |
| 走去茶水間、在位子上休息 | 閒置中 |
| 坐在茶水間的長椅上，頭上 🕒 | 排隊中 |
| 冒汗、頭上紅色驚嘆號 | 可能卡住了（到對話裡按「🔍 診斷」） |
| 拿著文件走到另一位成員的桌子 | 成員之間的交接 |
| 辦公室門牌 | 小組名稱與目前任務的狀態 |
| 彩帶 | 這個小組的任務完成 |

- 點辦公室門牌會拉近到那間辦公室，按「🗺 全景」回到整棟
- 點角色會打開和它的對話；滑鼠移上去可以看到職責、模型與狀態
- 晚上（依你電腦的時間）會變成夜間燈光
- 下方輸入框和全員頁一樣，可以開始任務或插話

角色與場景都是用程式畫的原創造型，構想參考了 Pixel Agents、pixtuoid、Agency HQ 等開源專案（沒有使用它們的程式碼或美術素材）。

### Google Antigravity 成員（engine: "agy"）

用來讓**不同家的模型互相檢查**（例如 Claude 寫、Gemini 覆核）。免費個人方案就能用，不需要訂閱高級方案，但有每週用量上限。

```
{ "id": "gem", "name": "小覆核", "role": "覆核 · 挑毛病", "engine": "agy",
```

| agyAccess | 做得到 | 做不到 |
|---|---|---|
| `read`（預設） | 讀檔、搜尋、用文字回覆意見 | 改檔案、執行指令（用計畫模式＋沙箱，並在每一輪之後檢查檔案） |
| `write` | 建立與修改檔案、**執行指令**（agy 預設模式，Windows 實測指令真的會執行） | 只靠提示詞要求它留在工作資料夾內；系統層面能不能擋住工作資料夾以外的讀寫還沒確認 |

> ⚠️ `write` 等級的 agy 成員等於可以在你的電腦上執行指令。在確認限制範圍之前，建議 agy 成員都用 `read`（覆核者），動手改檔交給 Claude／Codex 成員。

- 不使用 `--dangerously-skip-permissions`，也不提供這個選項
- **唯讀保險**：`read` 成員每一輪結束後，系統會比對資料夾；只要有檔案被改，就會自動暫停這位成員、在網頁與 Telegram 通知你，到「⚙️ 設定」按儲存才解除
- 提示詞用 stdin 傳給 agy（避免 Windows 引號問題）；如果你的 agy 版本不吃，在 `local-settings.txt` 加一行 `AGY_PROMPT_MODE=arg` 改用 `-p`（要直接執行 `agy.exe`）
- 唯讀參數可用 `AGY_READONLY_ARGS` 換掉（預設 `--mode plan --sandbox`）；可寫成員可用 `AGY_WRITE_ARGS` 加參數（預設不加，例如 `AGY_WRITE_ARGS=--sandbox`）；兩者都不能包含略過權限的參數。找不到指令時用 `AGY_BIN` 指定路徑
- ⚠️ `write` 成員的工作資料夾在 Agent Chat 程式資料夾裡面（例如預設的 `./workspace`）時，成員卡片會警告：它會執行指令，可能動到 Agent Chat 本身。建議把**整個小組**的工作資料夾改到外面，例如 `C:\agent-workspace`，並在 `local-settings.txt` 加 `AGENT_ALLOWED_ROOTS=C:\agent-workspace`（改完「🔄 只重新啟動」），再到各成員設定改工作資料夾
- ⚠️ Google 免費方案的資料可能被人工審閱；請自行確認送進去的內容可以交給 Google
- **用量**：agy 不提供剩餘額度。左下「用量額度」的 agy 區塊是 Agent Chat 自己統計的本週（週一起）輪數與 tokens，Telegram `/usage` 也有
- **🪫 額度用完**：agy 回報額度用完時，成員卡片顯示預計恢復時間（取自錯誤訊息，沒寫就先等 1 小時）。在那之前同事轉交、任務、排程不會交給它，派工的同事會收到通知請他改派；網頁與 Telegram 會通知你。你直接傳訊息給它會再試一次，成功就自動解除；到「⚙️ 設定」按儲存也能手動解除

## 9. 成員工作時插話

成員正在工作時，輸入框上方會出現送出方式可以選：

| 方式 | 作用 |
|---|---|
| ⚡ 立即插話 | 馬上中斷它這一輪，帶著你的指示接著做；同一段對話，之前做到哪裡、改了哪些檔案都保留 |
| 🕒 這輪做完再給 | 不中斷，等它這一輪做完再送出 |
| 📌 加入任務指示 | （任務進行中）不中斷，之後每位成員的每一輪都會看到，例如「檔案一律放在 workspace\lite」 |

- 全員頁在任務進行中也能輸入，預設是插話給正在工作的成員
- ⏹ 按鈕可以停止這位成員（全員頁是全部停止）
- 排隊中的成員卡片會顯示「🕒 排隊中（等某某做完）」，排隊中的訊息也會先出現在對話窗
- Telegram：成員工作時直接打字就是插話；`/later 訊息` 不中斷；`/note 指示` 加入任務指示

### ⚡ 緊急派工：PM 也能插話同事

PM（被授權的成員）在派工訊息裡寫 **【緊急】**，正在工作的同事會立刻暫停手上的事、先處理這件事，處理完系統會讓他**回頭繼續原本的工作**（同一段對話）。

- 授權：成員設定的「⚡ 可以緊急插話同事」；沒設定時，角色寫了 PM 的成員預設有，其他人沒有
- 只能插話同一小組的成員；對方正在寫交班筆記時不打斷
- 防止互相打斷：同一位對象在冷卻時間內（預設 5 分鐘，「⚙️ 工作流程」可改，0＝關閉）只會被緊急插話一次，也不能反過來插話剛插話過自己的人；不符合條件就改成一般排隊
- 被中斷的那一輪，檔案變更和中斷紀錄會記進任務；網頁和 Telegram 都會通知
- 代價：被中斷那一輪還沒說出口的思考會丟掉（檔案與對話紀錄不會），所以 PM 的提示詞會要求只在「方向改變、或會擋住別人」時才用

## 10. 使用小技巧

- **附加檔案**：把檔案拖到對話區、按 📎，或 Ctrl+V 貼上。檔案會存到該成員工作資料夾的 `attachments/`，訊息會自動附上路徑。成員只能讀自己工作資料夾裡的檔案，所以要給它們看的文件請用這個方式傳

- 對話會自動接續；重開伺服器後也會延續（記錄在 `data/` 資料夾）
- 電腦和手機同時開著時，畫面會即時同步
- 想看 agent 產生的圖，請它「把圖存在資料夾裡並在回覆中顯示」；只能顯示該 agent 工作資料夾裡的檔案

## 📋 部門待辦（LINE 群組 ＋ Google Sheet）

把 LINE bot 拉進部門群組，同事 @它 用自然語言登記待辦、查詢、更新；資料存在**你自己的 Google Sheet**（人也能直接改），每天早上自動寄 email 提醒。**不是正式紀錄**，是方便追蹤的輔助工具。

**用起來的樣子**（群組裡）
- `@待辦管家 週五前 完成校正紀錄`　→ 登記在你名下，期限換算成日期
- `@待辦管家 我的待辦`／`本週到期`／`逾期的有哪些`　→ 直接回覆
- `@待辦管家 #12 完成`／`#12 延到下週一`／`#12 備註 等試劑到`　→ 更新
- 缺資料時它會補問，並附按鈕（明天／本週五／不設期限…），點一下就好
- 在 Agent Chat 網頁直接跟待辦管家說話也行（例如「看一下 QA 的待辦」、「新增 …」），系統會以「管理員（主管）」身分處理
- 第一次用請說 `@待辦管家 我是 王小明`；想收提醒信再說 `@待辦管家 信箱 you@example.com`
- 它**只處理 @它（或以成員名稱、你設定的呼叫詞開頭）的訊息**，其他聊天不會看、不會記；群組的對話（包括系統直接回的登記、寫入結果）都會記在那位成員的對話框裡

**權限**：成員可以新增、改自己負責的；**主管**才能指派給別人、改別人的事項、取消事項。角色可以在 Sheet 的「成員」分頁改，或在群組說 `@bot 設定主管 @某人`／`取消主管 @某人`（只有主管、或一對一配對過 bot 的管理者可以；對方要先登記）。

**email 提醒**（Google 的定時功能，不耗 AI 額度、電腦關機也會寄）：每天約 8:30，每位負責人收到自己逾期／3 天內到期的事項，主管（成員分頁角色＝主管）與「設定」分頁的「總表收件人」收到部門總表。週末預設不寄。

**設定步驟**（約 10 分鐘，全在瀏覽器；左下「💚 LINE」→「📋 待辦清單」裡有逐步教學與一鍵複製程式碼）
1. 先完成上面「💚 LINE」的 6 步，並把官方帳號設定裡的「允許加入群組」打開
2. 新增成員：按「📋 套用待辦管家（部門群組）設定」（agy、唯讀，會勾好「📋 待辦清單能力」）
3. 用你的 Gmail 開一份新的 Google 試算表 → 擴充功能 → Apps Script → 貼上 `templates/todo/Code.gs`（設定視窗有複製按鈕）→ 回試算表選單「待辦機器人 → 初始化」
4. Apps Script「部署 → 網頁應用程式（執行身分：我、誰可以存取：所有人）」→ 複製網址；選單「顯示連線密鑰」→ 複製；貼到「📋 待辦清單」→ 儲存 → 測試連線
5. 試算表選單「安裝每日提醒信」；在「成員」分頁填姓名、Email、角色；在「設定」分頁填總表收件人
6. 在成員設定勾「💚 LINE 群組交給它」（或「💚 LINE」④ 選好按儲存）→ 產生配對碼 → 把 bot 拉進群組 → 在群組貼配對碼

> LINE 群組本身是通用的：交給**沒勾**「📋 待辦清單能力」的成員，就是一般對話（不附清單、不用登記）。

**安全設計**
- 待辦管家是 **agy 唯讀**：不能寫檔、不能執行指令。模型只在回覆裡寫「動作行」，**由 Agent Chat 驗證欄位、檢查發言者權限後才呼叫 Google**。群組裡有人叫它做別的事、或在事項裡塞假的動作行，都做不到
- Google 端要有「連線密鑰」才能讀寫（網址＋密鑰缺一不可）；密鑰存在 `agents.json`，不會出現在 API 回應或問題回報；懷疑外洩時到 Sheet 選單「重新產生密鑰」
- Sheet 欄位用名稱找（可調整順序、加自己的欄），事項用編號定位（可排序、插列）；每次更新都記錄「更新者」與時間，另有「紀錄」分頁

**安全防護（v3.22）**：送出前遮蔽所有密鑰；群組只能交給唯讀成員；沒在配對時被拉進陌生群組會自動離開；配對碼猜錯 10 次作廢；每人 10 分鐘最多叫 8 次；預先填好的主管不能被冒名認領。建議把待辦管家的工作資料夾改到 Agent Chat 程式資料夾外面。

**限制與提醒**
- 在群組裡回覆 @ 的訊息是免費的；若 AI 回很久（超過約 50 秒），改用推播，會算 LINE 訊息則數（群組可能依人數計算，額度以 LINE 官方為準）
- bot 跑在這台電腦：電腦睡眠或關機時 LINE 不會回應（email 提醒不受影響）。長期給部門用，建議放在常開的電腦、改用固定的公開網址
- 同事的訊息會經過 LINE、Google（agy 免費方案的資料可能被人工審閱）；事項裡請不要放機密資料
- LINE 沒有真正的多欄位表單，用「補問＋按鈕」取代
- 更新 Agent Chat 後如果 `Code.gs` 有變，要重新貼進 Apps Script（「測試連線」會顯示 Apps Script 的版本）

## 📊 唯讀資料表（例如儀器設備表）

## 💚 LINE（用 LINE 跟成員對話）

把「助理」（或任何成員）接到 LINE：在手機上傳訊息給它、收它的提醒。左下角「💚 LINE」裡有完整的 6 步教學與所有按鈕，這裡是重點。

**要準備的**：一個 LINE 帳號、約 10 分鐘。全部是網頁和手機操作。

1. 到 [manager.line.biz](https://manager.line.biz/) 建立一個 **LINE 官方帳號**（免費）
2. 在 LINE Official Account Manager：設定 → **Messaging API → 啟用**，選一個提供者（2024/9 起只能這樣開）
3. 設定 → **回應設定**：回應模式選 **Bot**、**Webhook 打開**；**「加入好友的歡迎訊息」和「自動回應訊息」關掉**
4. 到 [developers.line.biz/console](https://developers.line.biz/console/) → 你的 channel：Basic settings 最下面複製 **Channel secret**；Messaging API 最下面 **Channel access token (long-lived)** 按 Issue 後複製
5. Messaging API 分頁的 QR code 用手機 LINE 掃描，加好友
6. 回 Agent Chat「💚 LINE」：貼上兩個密碼、選要接的成員 → 儲存 → **「📡 一鍵開啟公開通道」** → 「🔍 檢查連線」→ 「產生配對碼」，把 6 位數字傳給 LINE 上的 bot。最後到 Developers 確認 **Use webhook** 是打開的

**公開通道**：LINE 只能把訊息送到公開網址。第一次用要下載 [cloudflared](https://github.com/cloudflare/cloudflared/releases/latest) 的 `cloudflared-windows-amd64.exe`，改名成 `cloudflared.exe`，放進 Agent Chat 資料夾（和 `server.js` 同一層）。之後按按鈕就會自動開通道、**自動把網址設到 LINE**；網址每次重開都會變，程式會自動重設，重新啟動時也會自動再開。有自己固定網址的（Tailscale Funnel、自己的網域），在「進階」欄位填網址，並把 `網址/line/webhook` 轉到 `127.0.0.1:3941`。

**在 LINE 上怎麼用**：直接傳文字。`/new` 開新對話、`/stop` 停止。成員提出提醒時會問你「同意 3」或「不要 3」。目前只收文字、只支援一對一聊天。

**訊息則數**：你傳訊息、它回覆（reply）**不算** LINE 的訊息則數；只有「回覆太久（超過約 50 秒）」和「排程提醒時間到、主動推播」會用掉推播額度。台灣的免費方案（輕用量）每月約 200 則（以 LINE 官方為準），設定畫面會顯示本月已用多少。用完後只能回覆你傳來的訊息。

**安全**
- LINE 的入口開在獨立連接埠（預設 3941，只聽 `127.0.0.1`），公開通道只接到這裡，**你的 Agent Chat 網頁（3939）不會被公開**
- 每個請求都驗證 LINE 的簽章，不對就 401；只有配對過的 LINE 帳號才轉給成員（配對碼 10 分鐘有效、只能用一次、錯 5 次鎖住）；其他人只會收到「還沒配對」
- Channel secret／token 存在 `agents.json`（和 Telegram token 一樣），不會出現在 API 回應或問題回報；要清除按「移除 LINE 設定」
- ⚠️ 你的訊息會經過 LINE 的伺服器，公開通道也經過 Cloudflare。**如果這是公司電腦，請先確認資安規定允許對外開通道**；工作上的機密資料不要透過 LINE 傳給成員

## 🗓 助理（個人秘書）

專門幫你安排行程、提醒、看排程、處理日常小事的獨立成員。

**建立**：左側「＋ 新增成員」→ 在「🧍 獨立成員」下方按「🗓 套用助理（個人秘書）設定」→ 儲存。會自動填好人設、**agy 唯讀**（gemini-3.8-flash-high；也可以改成 Claude）、Telegram 前綴 `/助理`、並勾選「每輪附上現況摘要」。助理**不需要讀寫檔案或執行指令**：行程與提醒都用「排程」記，查詢看系統附上的現況。

**怎麼用**（網頁或 Telegram 的 `/助理 …`）
- 「明天下午三點提醒我開會」「下週五 10:00 繳報告」→ 它提出一個排程建議（只做一次的排程＝一筆行程或提醒），你在「⏰ 排程」或 LINE 回「同意 編號」核准後，時間到系統就叫它提醒你
- 「這週有什麼行程？」→ 依系統附的「行程與提醒」清單回答；要取消就說「取消排程 編號」
- 「現在有哪些排程？有沒有異常？」→ 它依系統給的現況回答
- 「這週行程幫我排一下」「幫我擬一封請假的訊息」「待辦哪個先做？」
- 第一次建議說：「幫我設每天早上的行程摘要」，它會提出「平日 08:30」的排程

**時間可以這樣寫**：明天 15:00、後天下午3點、11/20 15:00、2026-12-01 09:30、週五 10:00、下週一 09:00、30 分鐘後、2 小時後；固定的：每天 08:30、平日 09:00、每小時、每 30 分鐘。單次的時間必須在未來；看不懂時，成員會收到說明並改寫。

**它能做、不能做**
- 能：看系統提供的現況（行程與提醒、固定排程、任務…）、用【排程建議】提出提醒、寫訊息草稿、算日期
- 不能：執行指令、讀寫檔案、自己新增或刪除排程（一律你核准）、看你的日曆、信箱或手機（只知道排程裡記過的行程）
- 想接 Google 日曆等：先到「🧰 CLI 狀態」確認 MCP 已連線，再到助理的成員設定「允許規則」加上該 MCP（例如 `mcp__日曆名稱`）

**想用 LINE 跟它聊**：見上面的「💚 LINE」。

**📋 每輪附上現況摘要**（成員設定的選項，其他成員也能勾）：現在的日期時間與時區、所有排程、等你核准的排程建議、進行中的任務、等你處理的守則建議與 Skill 申請。每輪多約 300～800 字，沒勾的成員不會多帶。

## 🧩 Skill（跟成員說一句就能裝）

Skill 是給成員的「工作說明書＋工具包」（例如設計審美、PDF 處理、公司報表格式）。

**安裝方式（不用打指令）**
1. 跟任何一位成員說：「幫我找一個做○○的 Skill，裝給 Coder 用」。成員會在回覆裡寫一行【安裝 Skill】來源 → 對象
2. 系統從 GitHub 下載檢查，網頁「🧰 CLI 狀態 → 🧩 Skill」（左下角會有紅點）與 Telegram 會請你核准：可以看到來源、檔案清單、**有沒有可執行的腳本**、要裝在哪
3. 按「核准安裝」，系統自己裝好；相關成員下一輪就能用

也可以在 Skill 分頁直接貼 GitHub 來源（例如 `nutlope/hallmark` 或 GitHub 網址）。Telegram：`/skills` 看申請、`/skill 編號 ok` 核准（會再問一次確認）、`/skill 編號 no` 拒絕。

**安裝位置**
- 預設：成員所屬小組的工作資料夾（`.claude/skills/`），只影響那個小組的成員
- 全域（`~/.claude/skills`）：所有 Claude 成員，**也包括你自己在終端機用的 Claude**；核准時可以選

**安全**
- 成員只能「提出」，一定要你核准；成員本身不需要任何額外權限
- 只從 GitHub 公開 repo 下載；不執行 Skill 裡的任何東西；不跟隨符號連結；單一 Skill 最多 400 個檔案、10 MB
- 含腳本的 Skill 會用紅字警告：Skill 被使用時成員可能執行那些腳本，請確認來源可信
- 移除會搬到 Agent Chat 的 `data/skills-trash`，可以找回
- 目前只支援 Claude 成員；Codex、agy 的 Skill 只顯示

## 疑難排解

**成員一直沒回應、看起來卡住？** 成員卡片上會顯示「⏱ 工作中 X 分鐘」；超過 10 分鐘沒有任何輸出會標示「⚠️ 可能卡住」，並通知 Telegram。點進那位成員，按上方的「🔍 診斷」可以看到實際執行的指令、CLI 的錯誤訊息（stderr）與最後的輸出；按「📋 複製診斷資訊」可以貼給 Claude 協助判斷。也可以在診斷畫面停止這一輪或清除排隊。卡住判定的時間可以在 `agents.json` 加上 `"stallMinutes": 15` 調整。


**出問題、想請 Claude 幫忙查？** 按左下角「🐞 問題回報」，寫下發生了什麼事，按「📦 產生回報檔」：會下載一個 `agentchat-report-日期-時間.md`（也存在 `data/reports/`），**把這個檔案拖進 Claude 的對話**就能排查。在手機上可以傳 Telegram `/report 發生了什麼事`，bot 會把檔案傳給你，轉給 Claude 就好。
回報裡有：版本、git 版本、Windows／Node.js／CLI 版本、成員設定與狀態、小組與流程、進行中的任務（含 TASK.md）、最近的錯誤與事件、網頁端錯誤、Telegram 狀態、伺服器紀錄（包含上次重新啟動或當機前的紀錄）。密碼、token、API 金鑰與成員環境變數的值會自動遮掉；預設不含對話內容，要附上就勾「附上每位成員最近 15 則對話內容」。伺服器紀錄也會存在 `data/logs/server.log`。

**git pull 之後出現「not found」或黃色提醒？** `git pull` 只會更新檔案，正在跑的伺服器還是舊程式。按左下角「⬆️ 更新／重新啟動」→「🔄 只重新啟動」，或關掉黑色視窗再重開 start.bat。


**回覆下方的「≈API價 US$…」是什麼？** 這是 Claude Code 估算「如果改用 API 計費大約要多少錢」，只是讓你參考這一輪用量大不大。用 Claude 帳號（Pro / Max）登入時，用的是訂閱額度，**不會另外收費**。除非電腦上設定了 `ANTHROPIC_API_KEY` 環境變數，Claude Code 才會改走 API 計費。


| 狀況 | 處理方式 |
|---|---|
| 「無法啟動 claude / codex」 | 先在終端機輸入 `claude --version`、`codex --version`，確認裝好了 |
| 回覆是登入或驗證錯誤 | 在終端機直接執行 `claude` 或 `codex` 重新登入 |
| 想換 port | 在 local-settings.txt 加 `PORT=4000` |
| 指令不在 PATH 裡 | 用 `CLAUDE_BIN`、`CODEX_BIN` 環境變數指定完整路徑 |

## 安全修補（2026-11-14）
- 所有 API（包含 localhost）均須登入。首次執行時，隨機密碼會顯示在 start.bat 的黑色視窗（只顯示一次），本機只保存 `data/admin-password-hash.json`；已有 ACCESS_TOKEN 環境變數時沿用。**忘記密碼**：刪除 `data/admin-password-hash.json` 再重開 start.bat，會產生新密碼。登入時勾「記住這台電腦 30 天」，伺服器重開或更新後就不用重新登入（只保存 session 雜湊在 `data/remembered-logins.json`，換密碼會全部失效）；左下角「🔒 登出」可以登出所有裝置。
- Web 會話使用 HttpOnly / SameSite=Strict Cookie，未再使用 URL token / localStorage。
- 遠端連線請配合 Tailscale，設定 `HOST` 與 `ALLOWED_HOSTS`；勿將 3939 port 公開到網際網路。
- Agent 工作目錄預設只能在 `workspace/` 下；若需要其他根目錄，先建立資料夾再以 `AGENT_ALLOWED_ROOTS` 白名單設定，Windows 多個目錄以分號區隔。
- 遠端控制端不接受 Claude `bypassPermissions`、Codex `danger-full-access`；需要全權限時請在本機終端機手動操作。
- Claude 的 `--add-dir` 無法保證指定目錄唯讀，故不再接受 Claude 額外資料夾 ro 模式；請提供受 OS ACL 保護的資料副本。
- 子程序環境變數採白名單，預設不傳 ACCESS_TOKEN、TELEGRAM_BOT_TOKEN 等控制端機密，也不傳 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`（避免意外改走 API 計費）。Windows 系統變數、公司網路的 proxy 與憑證設定（`HTTPS_PROXY`、`NODE_EXTRA_CA_CERTS` 等）會保留。需要其他變數時用 `AGENT_ENV_ALLOWLIST` 明確加入（逗號分隔）。
- Telegram 僅接受私人聊天室指令與推播，並以 allowedUserIds 與聊天室 userId 雙重檢查；撤銷配對後立即停止推播。
- 既有設定如使用白名單以外的工作目錄、危險權限或 Claude 唯讀資料夾，伺服器仍會啟動，但**那位成員會暫停使用**，卡片顯示「⛔ 設定需修正」，送訊息時會說明原因；修正設定（或在 local-settings.txt 設定 `AGENT_ALLOWED_ROOTS`）後即可恢復。
- 任務交接：預設只在 🔒 階段等你核准。在「⚙️ 工作流程」可以打開「🛡️ 交給有寫入權限的成員時，一律要我核准」，降低成員讀到惡意內容後自動連鎖執行的風險。
- 安全測試：`node --test tests/security.test.js tests/http.test.js`。
